# Kiddie Tube

A kid-friendly, curated YouTube player: an installable PWA (Vite + React +
TypeScript). Currently deployed to GitHub Pages at `/KiddieTube/`; moving to a
self-hosted, multi-family app at `kids.tinyapps.dev`. See
[docs/ROADMAP.md](docs/ROADMAP.md) for the plan and
[docs/adr/](docs/adr/) for architecture decisions.

## Repository layout

```
apps/web/          the web app (PWA)
  src/             app code (+ *.test.ts unit tests next to the code)
  e2e/             Playwright end-to-end tests (YouTube stubbed)
  public/          static files, incl. videos.json (bundled seed list)
apps/api/          server API (Fastify, Drizzle, Better Auth)
packages/shared/   types + validation shared by web and API
deploy/            home-server deployment (systemd, nginx, deploy.sh)
docs/              roadmap, ADRs
```

npm workspaces: run commands from the repo root.

## Development

Requires Node 20.19+ (Vite 7).

```bash
npm install
npm run dev          # http://localhost:5173/KiddieTube/
npm run lint         # ESLint, all workspaces
npm run typecheck    # TypeScript, all workspaces
npm test             # unit tests (Vitest)
npm run test:e2e     # end-to-end tests (Playwright; Chromium + WebKit)
npm run build        # type-check + production build -> apps/web/dist
npm run preview      # serve the production build
```

First e2e run on a machine: `npx -w @kiddietube/web playwright install chromium webkit`.

### Server mode (multi-family, self-hosted)

The self-hosted version (`kids.tinyapps.dev`) is the same web app built with
`VITE_SERVER_MODE=true`, talking to the API in `apps/api`. Run both locally
(the API uses an embedded PostgreSQL, PGlite, so nothing to install):

```bash
ADMIN_EMAILS=you@example.com FAKE_YOUTUBE_META=true npm run dev -w @kiddietube/api   # :3007, data in apps/api/.data/dev
VITE_SERVER_MODE=true BASE_PATH=/ npm run dev -w @kiddietube/web                    # proxies /api to :3007
```

Open `/join` to create the first (admin) account, create a family, add
categories/videos, then **Kids → Use this device**. Without
`RESEND_API_KEY`, emails (invites, password resets) are printed to the API log.

```bash
npm test -w @kiddietube/api       # API integration tests (PGlite, RLS enforced)
npm run test:e2e:server           # real API + server-mode build, end to end
```

Deployment to the home server: [deploy/README.md](deploy/README.md).

**Base path:** the build defaults to `/KiddieTube/` (GitHub Pages). For hosting
at a domain root, build with `BASE_PATH=/` (e.g. `BASE_PATH=/ npm run build`).

The web app manifest and service worker are generated by `vite-plugin-pwa`
(configured in `apps/web/vite.config.ts`).

## Quality gates

- **Every PR** runs `.github/workflows/ci.yml`: lint, typecheck, unit tests,
  build, and the e2e suite on desktop Chrome, Android Chromium and iPhone
  WebKit.
- **Every push to `master`** runs the same CI first, then builds and deploys.

## Deployment

`master` is what's live. Every push to `master` runs
`.github/workflows/deploy-gh-pages.yml`: CI, then build and publish
`apps/web/dist` with GitHub Pages Actions (repo Settings -> Pages -> Source:
"GitHub Actions"). It can also be re-run by hand from the Actions tab
(workflow_dispatch). Work happens on branches and reaches the site by merging a
PR into `master`.

## Parent panel (add / edit / remove videos)

The video list can be managed at runtime without touching `videos.json`.

**Open it** (hidden from kids): press-and-hold the header logo for ~0.7s, or
visit the app with `?parent=1` in the URL. Set an optional PIN in the Sync tab
to gate re-opening. The panel always closes on reload.

**What it does**
- **Add**: paste a YouTube link (or an 11-char video ID). The title is fetched
  automatically via YouTube's public oEmbed endpoint and stays editable; pick a
  category from the existing list or type a new one.
- **Edit / Hide / Delete**: per-row in the Videos tab. **Hide** removes a video
  from the kids' page but keeps it in the list (dimmed, tagged "Hidden");
  **Unhide** brings it back. Filter the list by All / Visible / Hidden.
- **Order**: videos added from the panel are shown first, newest on top; the
  bundled videos follow in their original order.

## Themes

The parent panel's **Theme** tab switches the app's look: ☀️ **Sunny**
(default), 🐳 **Ocean**, 🍭 **Candy** and 🎨 **Classic** (the original v2
design). The choice is saved **on that device only** (`localStorage`), never
synced through the Gist, so each device can look different.

- Tokens: `--kt-*` custom properties on `:root` in `src/styles-v2.css`; their
  defaults are the Classic design.
- Themes: `src/themes.css` overrides the tokens per `<html data-theme="…">`.
- List / default / persistence: `src/lib/theme.ts`. `index.html` applies the
  saved theme before first paint (keep its id list in sync).

To add a theme: add a block to `themes.css`, an entry to `THEMES` in
`theme.ts`, and its id to the regex in `index.html`.

## Player

Custom controls over the YouTube player: play/pause, ±10s, seek bar,
fullscreen, and a **speed** button that cycles 0.5x → 0.75x → 1x → 1.25x → 1.5x
(limited to what the video supports). The chosen speed is remembered on the
device and re-applied to every video.

**Where changes are stored** (`src/lib/videoStore.ts`)
1. If a shared GitHub Gist is configured on the device, edits are written there
   and every other device picks them up on next open.
2. Otherwise edits persist to `localStorage` on that device only.
3. The bundled `public/videos.json` is always the seed / fallback.

**Enabling cross-device sync** — in the panel's *Sync* tab:
1. Create a GitHub personal access token with the **`gist`** scope only.
2. Paste it and press **Create shared list** (makes a secret Gist), or paste an
   existing token + Gist ID and press **Connect to Gist**.
3. Repeat step 2 on other devices with the same token + Gist ID.

The token is stored in `localStorage` on that device; "Remove token from device"
clears it. "Reset list to bundled videos" restores `videos.json`.
